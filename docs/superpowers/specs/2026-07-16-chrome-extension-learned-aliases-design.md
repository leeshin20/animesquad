# Chrome Extension 학습형 애니 별칭 설계

## 목표

스트리밍 사이트에서 감지한 작품명이 AnimeSquad에 저장된 제목과 달라 자동 검색에 실패했을 때, 사용자가 수동으로 선택한 작품과 감지 제목의 관계를 학습한다. 이후 같은 감지 제목은 기존 애니 검색 API에서 자동으로 해당 작품과 매칭되어야 한다.

예시:

- DB 한국어 제목: `도굴왕`
- 스트리밍 사이트 감지 제목: `(자막) 도굴왕`
- 최초 사용자가 `도굴왕`을 수동 선택하고 감상 기록에 성공
- 해당 애니의 `search_keywords`에 `(자막) 도굴왕` 추가
- 다음 감상부터 `(자막) 도굴왕` 검색으로 `도굴왕` 자동 매칭

## 범위

이번 변경은 기존 `anime.search_keywords` 컬럼과 `/api/anime/search` 검색 로직을 재사용한다. 별도 별칭 테이블이나 DB 마이그레이션을 추가하지 않는다. 별칭은 스트리밍 사이트별로 구분하지 않고 모든 사이트에서 공통으로 사용한다.

화수 기록 흐름은 현재 동작을 유지한다. 확장 프로그램이 제목에서 화수를 감지해 팝업에 미리 입력하고, 사용자가 `기록하기`를 눌렀을 때 회차 평가 또는 진도로 저장한다. 사용자 확인 없이 자동 저장하지 않는다.

## 백엔드 설계

### API

인증된 사용자가 호출할 수 있는 전용 엔드포인트를 추가한다.

```http
POST /api/anime/{animeId}/aliases
Content-Type: application/json

{
  "alias": "(자막) 도굴왕"
}
```

성공 시 갱신 여부와 관계없이 `204 No Content`를 반환한다. 존재하지 않는 애니는 `404 Not Found`, 비어 있거나 200자를 초과한 별칭은 `400 Bad Request`, 인증되지 않은 요청은 `401 Unauthorized`를 반환한다.

### 서비스

`AnimeAliasService`가 별칭 추가만 담당한다.

1. 별칭의 앞뒤 공백을 제거한다.
2. 빈 값과 200자 초과 값을 거부한다.
3. 대상 애니를 갱신 잠금으로 조회한다.
4. 기존 제목 또는 `search_keywords` 때문에 같은 별칭 검색이 이미 해당 애니를 반환한다면 변경하지 않는다.
5. 기존 `search_keywords`가 비어 있으면 별칭만 저장한다.
6. 기존 값이 있으면 `기존 값, 새 별칭` 형식으로 추가한다.

갱신 잠금은 동시에 여러 사용자가 같은 애니에 서로 다른 별칭을 추가할 때 마지막 저장만 남는 문제를 방지한다. 기존 관리자 키워드 편집 형식인 쉼표 구분 문자열을 유지한다.

## Chrome Extension 설계

팝업은 pending 데이터의 최초 감지 제목을 `detectedAnimeName`으로 보관하고, 선택 출처를 추적한다.

- Service Worker 검색 결과의 첫 항목을 자동 선택한 경우: `manualMatch = false`
- 검색 결과가 없어 검색창에서 사용자가 작품을 클릭한 경우: `manualMatch = true`

`기록하기`의 처리 순서는 다음과 같다.

1. 워치리스트 미등록 작품이면 `POST /api/watch`로 추가한다.
2. 평점 또는 한줄평이 있으면 회차 평가 API를 호출한다.
3. 둘 다 없으면 진도 API를 호출한다.
4. 감상 기록이 성공하고 `manualMatch = true`이면 별칭 API를 호출한다.
5. pending 데이터와 배지를 지우고 완료 화면을 표시한다.

자동 매칭된 작품에는 별칭 API를 호출하지 않는다. 사용자가 검색 결과를 클릭했더라도 감상 기록이 실패하거나 `무시`를 선택하면 별칭을 저장하지 않는다.

## 오류 처리

감상 기록과 별칭 학습의 성공 여부를 분리한다.

- 감상 기록 실패: 기존처럼 기록 실패를 안내하고 pending 데이터를 유지한다. 별칭 API는 호출하지 않는다.
- 감상 기록 성공 + 별칭 저장 성공: 기존 완료 화면을 표시한다.
- 감상 기록 성공 + 별칭 저장 실패: 감상 기록은 되돌리지 않는다. `기록은 완료됐지만 별칭 저장에 실패했어요.`라고 안내한 뒤 pending 데이터와 배지를 정리한다.

별칭 저장 실패 때문에 이미 성공한 감상 기록을 재시도하게 만들지 않는다.

## 보안과 데이터 무결성

- 별칭 추가 API는 로그인 사용자에게만 허용한다.
- 클라이언트가 전체 `search_keywords` 값을 보내거나 덮어쓰지 않는다. 서버가 단일 별칭만 받아 기존 값을 보존하며 추가한다.
- 별칭 길이를 200자로 제한해 임의의 대용량 입력을 막는다.
- API는 멱등적으로 동작해 같은 별칭을 반복 요청해도 중복 저장하지 않는다.
- 관리자용 애니 수정 API와 권한은 변경하지 않는다.

## 테스트

### 백엔드

- 기존 `search_keywords`를 보존하면서 새 별칭을 추가한다.
- 비어 있는 `search_keywords`에 첫 별칭을 추가한다.
- 같은 별칭을 반복 요청해도 중복 저장하지 않는다.
- 추가된 별칭으로 `GET /api/anime/search`가 대상 애니를 반환한다.
- 빈 값, 공백-only 값, 200자 초과 값을 거부한다.
- 존재하지 않는 애니와 인증되지 않은 요청을 거부한다.

### Chrome Extension

- 수동 검색 선택 후 감상 기록이 성공하면 감지 원문으로 별칭 API를 호출한다.
- 자동 매칭된 작품에는 별칭 API를 호출하지 않는다.
- 감상 기록 실패 시 별칭 API를 호출하지 않는다.
- 별칭 저장만 실패하면 감상 기록 완료 상태를 유지하고 별도 안내를 표시한다.
- 감지된 화수가 기존 회차 평가 또는 진도 요청에 그대로 전달된다.

## 스코프 외

- 별칭 전용 테이블 및 사이트별 별칭
- 사용자별 별칭
- 별칭 승인·신고·관리 이력
- 관리자의 기존 `search_keywords` 편집 UI 변경
- 사용자 확인 없는 감상 기록 자동 저장
