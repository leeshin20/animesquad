# 라프텔 작품 ID 기반 학습형 매칭

## 목적과 범위

사용자가 선택한 방식은 라프텔의 작품 ID를 AnimeSquad 작품에 연결하고, 이후 사용자에게 그 연결을 재사용하는 것이다. `(자막)` 같은 제목 표기 차이가 매번 수동 검색으로 이어지는 문제를 해결한다. 기존 별칭 학습과 사용자가 확인한 뒤 감상을 저장하는 흐름은 유지한다.

이번에는 실제 검증한 라프텔 웹 플레이어만 지원한다. 넷플릭스 ID 연결, 플랫폼별 회차 번호 변환, 회차 바로가기 UI, 관리자 매핑 관리 UI, 사용자 확인 없는 감상 저장은 포함하지 않는다. 시즌 합본 등 회차 변환이 필요한 작품은 이 버전의 작품 단위 연결 대상으로 삼지 않는다.

## 검토한 방식

- 제목의 `(자막)` 등을 제거하는 방식은 최초 검색을 도울 수 있지만, 플랫폼 제목 변경이나 다른 작품 간 혼동을 해결하지 못한다.
- 기존 공용 별칭 학습은 유지하되 플랫폼·작품 ID 연결을 먼저 조회하는 방식을 사용자가 선택했다. 확장에서 확인한 `/player/41666/65123`의 `41666`이 작품 ID이고 `65123`은 회차 ID다. 회차가 바뀌어도 같은 작품 연결을 재사용한다.

## 동작

1. 서비스 워커가 감지 메시지를 보낸 탭 URL에서 라프텔 플레이어인지 확인하고 작품 ID를 추출한다. 작품 상세 페이지는 완료 감지 대상으로 처리하지 않는다.
2. 서버에서 `LAFTEL + 작품 ID`에 해당하는 연결을 조회한다. 연결이 있으면 반환된 작품을 자동 선택하며 제목이 변경돼도 연결 결과를 유지한다.
3. 연결이 없거나 조회가 일시적으로 실패하면 기존 제목 검색으로 넘어간다. 라프텔에서는 원래 제목 또는 기존 별칭이 정확히 일치하는 단일 작품만 자동 선택한다. 결과가 여러 개이거나 정확 일치가 없으면 사용자가 직접 선택한다. 부분 검색의 첫 항목을 확정된 작품으로 취급하지 않는다.
4. 사용자가 기록하기를 눌러 감상 저장이 성공하면 선택한 작품과 라프텔 작품 ID 연결을 저장한다. 기존 수동 선택에 따른 제목 별칭 학습도 유지한다. 저장 실패·무시·검색 결과 선택만으로는 연결을 학습하지 않는다.
5. 같은 ID와 같은 작품을 재등록하는 것은 성공으로 처리한다. 다른 작품이 이미 연결되어 있으면 충돌로 반환하며 기존 연결을 덮어쓰지 않는다. 현재 사용자가 선택한 작품의 감상 저장은 유지한다.
6. 연결 저장만 실패하면 기록 완료와 연결 학습 실패를 구분해 안내한다. 이미 성공한 감상 저장을 다시 요청하도록 유도하지 않는다. 충돌한 선택을 별칭으로 자동 전파하지 않는다.

## 데이터와 API

- 새 테이블은 플랫폼, 플랫폼 작품 ID, AnimeSquad 작품 ID를 저장한다. 플랫폼·플랫폼 작품 ID는 유일하며, 여러 라프텔 작품 ID가 동일 AnimeSquad 작품을 가리킬 수 있다.
- 작품 삭제·제외 시 연결은 함께 제거해 존재하지 않는 작품을 자동 선택하지 않는다.
- 연결 조회는 기존 작품 검색처럼 공개한다. 연결 등록은 인증된 사용자만 가능하다. 숫자 형식의 양수 라프텔 작품 ID만 허용한다.
- 연결이 없는 조회는 404, 동일 연결 등록은 204, 다른 작품에 대한 중복 연결은 409로 처리한다. 동시 최초 등록에서도 연결 하나만 저장되도록 DB 유일성 제약을 사용한다.
- 확장 이전 버전과 넷플릭스·크런치롤은 기존 API와 메시지 형식으로 계속 동작한다. 새 필드는 추가 필드로 전달한다.

## 검증 기준

- 최초 사용자의 감상 저장 후 같은 라프텔 작품 ID를 다른 사용자와 다른 제목으로 조회해도 같은 AnimeSquad 작품을 얻는다.
- 회차 ID가 달라져도 같은 작품 ID 연결을 사용하고 감지한 회차 숫자는 그대로 기록한다.
- 미등록 ID, 잘못된 URL, 인증되지 않은 등록, 같은 연결 재등록, 상충하는 연결, 조회·학습 장애를 검사한다.
- 감상 저장 실패·무시에는 연결 등록이 없고, 연결만 실패한 경우 감상 저장은 한 번만 이뤄진다.
- 정확 일치 별칭은 재사용하며 본편·외전 등의 모호한 검색 결과에서 첫 작품을 임의로 자동 선택하지 않는다.
- 기존 확장 테스트와 백엔드 전체 테스트를 실행한다. 실제 운영 데이터에는 테스트용 감상을 저장하지 않는다.

## 구현자 판단

앞의 충돌 처리, 정확 일치 제한, API 응답 코드는 사용자 선택을 안전하게 구체화한 구현 제안이다. 별도 승인·투표 시스템은 만들지 않으며, 매핑 관리 화면과 회차 범위별 연결은 후속 작업으로 남긴다.
