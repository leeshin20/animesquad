# 자동 시청 기록 중심의 스쿼드 경험

날짜: 2026-10-26
상태: 사용자 승인 완료 — 구현 중

## 의도와 합의

사용자가 애니를 보면 기록이 쌓이고, 서비스에 돌아와 스쿼드원들이 본 작품을 살펴본다. 감상평은 이미 남은 기록에 원할 때 덧붙이는 표현이다. 감상평을 작성하지 않은 시청 기록도 완전한 기록으로 취급한다.

사용자가 선택한 범위는 단순 문구 교체를 넘어선 핵심 흐름 전환이다. 자동 기록 중심의 피드, 연속 회차 묶기, 선택적인 감상평, 향후 주기적인 통계·리캡의 데이터 기반을 포함한다. 홈의 중심은 스쿼드 활동으로 유지한다.

## 검토한 접근

1. 문구·입력창만 간소화: 작은 변경으로 작성 부담을 줄이지만, 스쿼드 활동에 의존하는 개인 이력과 리캡의 근거 문제는 남는다.
2. **시청 이력을 독립적으로 저장하고 핵심 흐름 전환 — 사용자 선택**: 원본 이력은 회차별로 보존하고, 피드에서만 묶는다. 구현 범위는 커지지만 소셜 피드와 후속 리캡에 같은 근거를 사용할 수 있다.

새로운 소셜 서비스나 리캡 제품 전체를 만드는 범위는 아니다. 기존 Spring/PostgreSQL, Next.js, 확장 프로그램과 배포 구조를 사용한다.

## 확인한 현재 제약

- `WatchEntry.progress`는 현재 진도 한 숫자다. 특정 회차를 언제 기록했는지는 알 수 없다.
- 진도 활동은 가입한 스쿼드마다 Activity로 복제된다. 스쿼드가 없으면 생성되지 않으며, 스쿼드를 삭제하면 함께 삭제된다.
- 회차 감상평을 쓰면 같은 회차의 단순 진도 Activity를 삭제한다. 개인 이력을 이 Activity에 의존하면 감상 작성 여부에 따라 기록이 사라진다.
- 홈에서 `+ 감상 기록`을 누르면 평점·감상평 입력창이 바로 열린다. 서버에서는 선택 항목이지만 사용 흐름에서는 평가가 중심이다.
- 라프텔은 현재 재생 위치가 전체 길이의 80% 이상인지를 검사한다. 실제로 재생한 누적 시간이나 빠진 회차를 증명하지 않는다.

## 목표와 제외 범위

### 목표

- 자동 기록 성공 후 추가 확인이나 감상 입력 없이 끝난다.
- 스쿼드 미가입자도 개인 시청 이력을 보존한다.
- 중복 감지·재시도·여러 스쿼드 때문에 기록이나 통계가 중복되지 않는다.
- 실제 기록된 연속 회차만 피드에서 묶는다. 건너뛴 회차를 봤다고 추정하지 않는다.
- 감상 작성·수정·삭제가 시청 시각과 시청 기록 수를 바꾸지 않는다.
- 리캡에 필요한 회차, 최초 기록 시각, 기록 경로를 남긴다.

### 이번에 하지 않을 것

- 리캡 화면, 정기 발송, 통계 API 전체, 실제 시청 시간 측정.
- 재시청 횟수 집계, 재생 위치 이어보기, 넷플릭스·크런치롤의 새로운 자동 기록 방식.
- 알림·댓글·반응·공유 범위 설정 같은 소셜 기능 추가.
- 기록만으로 작품 상태를 자동으로 COMPLETED로 바꾸기. 기존 사용자 상태는 보존한다.
- 확인할 수 없는 과거 회차나 시청 날짜를 만들어내기.

## 기본 사용자 흐름

### 자동 기록

라프텔의 기존 80% 판정과 작품 ID 매칭을 유지한다. 성공하면 `N화 시청 기록 저장 완료`로 끝나고 감상 작성창을 자동으로 열지 않는다. 고정 표시 `🟢 자동 기록 중`, 계정·작품·재생 진행 정보, 최초 작품 연결과 로그인 필요 안내는 유지한다.

확장 팝업의 기록 기본 동작도 평점·감상평 없이 `시청함`으로 처리한다. 감상 입력은 명시적으로 `감상 남기기`를 눌렀을 때만 열린다. 최초 수동 매칭은 기록 성공 후 작품 ID를 연결하는 기존 규칙을 유지한다.

확장 변경을 배포할 때는 1.0.7로 올린다. 이전 1.0.6 자동 기록 요청도 새 서버에서 계속 동작해야 한다.

### 웹의 수동 기록과 감상

- 홈·내 작품·상세의 다음 회차 기본 작업은 `N화 시청함`이다. 성공·진행·실패 상태를 표시하며 중복 클릭을 막는다.
- 다른 회차 선택은 보조 작업 `회차 선택`으로 제공한다. 평점·감상평 입력 없이 선택 회차를 기록할 수 있다.
- 이미 기록한 회차에서 `감상 남기기`를 누르면 해당 회차를 미리 선택한다. 기존 감상이 있으면 불러와 수정한다. 다음 회차로 잘못 이동하지 않는다.
- 아직 기록하지 않은 회차에 감상을 남기는 기존 경로는 유지한다. 이 경우 해당 회차의 시청 기록도 한 번 생성한다.
- 작품 전체 감상과 회차 감상은 유지한다. 감상에 별점·글이 전혀 없으면 새 감상을 만들지 않고 기존 감상 삭제는 별도 확인 작업으로 처리한다.
- 시청 기록에 `별점 없음`, `감상 미작성` 같은 결핍 표시는 하지 않는다.
- 작품 상태·전체 진도 수정은 보조 관리 기능으로 유지한다.

### 홈과 내 기록

홈의 중심은 스쿼드 활동으로 유지한다. 내 작품 영역은 `최근 본 애니`로 표현하고 기본 작업을 시청 처리로 바꾼다. 비로그인 소개도 `시청 기록을 자동으로 쌓고, 스쿼드와 함께 나누세요`로 맞춘다.

탐색 구조는 `내 기록` 안의 `작품 / 시청 기록 / 감상평`으로 정리한다. 기존 `/watchlist/anime`, `/watchlist/reviews` 주소를 유지하고 시청 이력용 `/watchlist/history`를 추가한다. 감상평 탭은 실제 평점이나 글이 있는 항목만 보여주고, 시청 기록 탭은 아래 독립 이력을 보여준다. 감상평만 지워도 시청 기록에는 남는다.

설치 여부를 알아내는 새로운 확장 연결 프로토콜은 만들지 않는다. 빈 기록 화면에 기존 배포·설치 경로가 확인되는 경우 해당 안내를 연결한다. 연결 상태를 추측해서 표시하지 않는다.

## 원본 시청 이력

### 저장 단위

`episode_watch` 테이블을 추가한다.

- `id`, `user_id`, `anime_id`, `episode_number`.
- `recorded_at`: 서버가 최초 기록을 수락한 시각. 실제 재생 시간이라는 의미는 아니다.
- `source`: `EXTENSION / MANUAL / UNKNOWN / LEGACY`. 기록 경로이며 접근 권한 판단에는 쓰지 않는다.
- `(user_id, anime_id, episode_number)` 유일 제약, 양의 회차 제약, 사용자·시각 조회 인덱스.
- 사용자와 작품을 참조한다. 계정 삭제 시 함께 제거한다. 이력이 존재하는 작품의 관리자 단건·일괄 삭제는 기존 시청 목록과 마찬가지로 차단한다.

이번 집계 단위는 사용자별 작품·회차의 최초 기록이다. 재시청은 중복 생성하거나 최초 기록 시각을 갱신하지 않는다. 감상평 수정도 최초 시각을 바꾸지 않는다. 작품의 전체 화수가 미정일 수 있으므로 회차는 양의 정수로 검증하고 기존과 같이 전체 화수를 서버의 강제 상한으로 쓰지 않는다.

### 쓰기와 기존 API 호환

기존 `POST /api/watch/{animeId}/progress`의 `{ progress }`와 WatchEntry 응답 구조는 유지한다. `source`는 선택 입력으로 추가하고 생략 시 UNKNOWN이다. 갱신된 확장은 EXTENSION, 웹 수동 기록은 MANUAL을 보낸다.

이 요청은 **선택된 N화 한 회차**를 시청한 것으로 기록한다. 2화에서 5화로 이동해도 3·4화를 만들지 않는다. 트랜잭션에서 다음을 처리한다.

1. 동일 사용자·작품의 쓰기를 직렬화하고 `episode_watch`를 충돌 무시 방식으로 삽입한다.
2. 현재 작품 진도는 기존과 같이 최댓값만 반영한다. 상태·기존 감상은 보존한다.
3. 회차 이력이 새로 삽입된 경우에만 현재 가입한 스쿼드에 피드 이벤트를 만든다. 진도보다 낮은 회차라도 처음 확인된 회차이면 기록한다.

최초 WatchEntry 생성, 같은 회차 동시 요청, 다른 회차 동시 요청도 DB 제약·잠금 순서로 일관되게 처리한다. 이력·진도·피드가 부분 성공하지 않게 한다.

회차 감상 저장도 같은 회차 이력을 없을 때만 생성하고 실제 저장된 평점·글로 감상 이벤트를 만든다. 기존 감상 수정은 시청 이벤트를 다시 만들지 않는다. 같은 회차의 시청과 감상 동시 요청은 한 시청 이력으로 수렴한다.

기존 PATCH의 진도 입력은 `N화까지로 진도 수정`이라는 관리 작업으로 남긴다. 이력 회차를 채워 넣거나 과거 이력을 지우지 않는다. 새로운 시청 처리는 POST만 사용한다. 예전 확장 팝업의 PATCH 수동 기록은 진도 수정으로 계속 동작하지만, 완전한 회차별 기록에는 확장 업데이트가 필요하다.

### 개인 이력 API와 삭제

`GET /api/me/episode-watches?cursor={id}&limit=50`은 본인 이력과 작품·회차·recordedAt·source를 ID 내림차순으로 반환한다. 기본 50, 최대 100이며 마지막 원본 ID로 다음 페이지를 요청한다. 시청 기록 탭은 필요할 때 더 불러오고 전체 이력을 최근 500개로 고정 제한하지 않는다.

`DELETE /api/me/episode-watches/{id}`는 본인 이력만 삭제하고 연결된 모든 스쿼드의 시청 활동을 제거한다. 그 회차에 감상이 있으면 감상을 먼저 지우도록 409로 안내한다. 감상은 별도 삭제이며 이력 삭제가 감상을 몰래 없애지 않는다.

삭제 대상이 현재 진도와 같으면 진도를 N-1로 내리고, 더 낮은 과거 회차라면 현재 진도는 보존한다. 상태·작품 감상은 보존한다. 삭제 후 확장에서 같은 회차를 다시 감지하면 새로 기록할 수 있다는 점을 확인 문구로 안내한다. 이미 해당 탭에서 저장 완료로 표시된 회차는 기존 중복 방지 때문에 새 감지·새로고침 후에 재기록될 수 있다.

과거 `/api/me/progress-activities` 조회·삭제는 기존 동작을 호환 유지하지만 새 화면은 사용하지 않는다. 새 시청 활동을 이 API로 삭제할 경우에도 연결된 episode_watch 삭제 정책으로 위임해 원본과 피드가 어긋나지 않게 한다. 연결이 없는 옛 Activity의 기존 삭제 의미는 유지한다.

작품을 내 목록에서 제거하면 해당 작품의 이력·회차 감상·피드도 함께 제거한다는 확인을 표시하고 하나의 트랜잭션으로 삭제한다. 감상평만 삭제하는 작업은 이와 구별한다. 계정 삭제·관리자 작품 삭제의 참조 검사도 새 테이블을 포함한다.

## 피드 표시와 묶기

원본 회차 이력을 합치거나 삭제하지 않는다. 새 시청 Activity payload에 `episodeWatchId`와 실제 `episode`를 넣고 기존 `progress`도 호환 유지한다. 피드 생성은 당시 가입한 스쿼드에 한정하며 나중에 가입한 스쿼드로 과거 기록을 소급 공개하지 않는다. 기존 스쿼드별 권한 검사를 유지한다.

### 묶기 기준 — 아래는 구현 제안

- 같은 사용자·작품의 실제 연속 회차만 묶는다.
- 회차별 기록 시각 간격이 **2시간 이내**여야 한다. 자정을 지나도 이 조건이면 묶인다.
- 그 사용자가 중간에 다른 작품을 기록했다면 다른 묶음으로 나눈다. 다른 사람의 활동은 묶음을 끊지 않는다.
- 1·2·3화는 `1~3화 시청`, 1·3화는 각각 표시한다. 순서를 거꾸로 기록하거나 중간 회차가 빠지면 범위로 추정하지 않는다.
- 묶음 시각과 정렬은 가장 최근 회차 기준이다. 다른 사람의 활동 사이에 있는 앞선 회차가 최신 묶음으로 모일 수 있다.
- 시청 활동은 간단한 작품·회차 표시로 표현하고 감상평은 내용이 보이는 별도 활동으로 표현한다.
- 같은 회차 감상이 표시되는 조회 범위에서는 해당 단일 시청 활동을 중복 표시하지 않는다. 남은 시청 활동만 연속성에 따라 묶는다. 감상 삭제 시 원래 시청 활동이 다시 보인다. 따라서 감상 저장 시 시청 Activity 자체를 삭제하지 않는다.

홈과 스쿼드 상세에 같은 순수 표시 함수를 사용한다. 필터링·중복 축약·묶기를 완료한 뒤 화면 표시 개수를 계산한다. 스쿼드 상세는 기존 원본 Activity 커서로 다음 페이지를 받고, 누적 원본 전체를 다시 묶어 페이지 경계의 연속 회차도 합친다. 묶음의 가상 ID를 서버 커서로 사용하지 않는다. 묶인 표시 항목 수로 서버의 마지막 페이지를 판정하지 않는다.

홈은 권한 확인된 각 스쿼드 피드를 기존과 같이 합친다. 같은 episodeWatchId의 복제본은 한 번만 표시하고 공유된 스쿼드 배지를 함께 표시한다. 다른 회차·다른 사용자·서로 다른 스쿼드 공개 범위를 무조건 섞지 않는다. 한 묶음은 공유된 스쿼드 집합도 같아야 한다. 구형 이벤트는 확실한 공통 ID가 없으면 기존 행으로 보존한다.

묶기는 불러온 원본 범위에 적용한다. 아직 조회하지 않은 기록까지 묶였다고 보장하지 않는다. 추가 페이지를 받으면 묶음이 확장될 수 있다. 홈의 각 스쿼드 최근 50개 조회 범위 확대나 통합 홈 커서 API는 이번 범위가 아니다.

## 기존 데이터와 리캡의 정확도

마이그레이션은 남아 있는 PROGRESS_UPDATED의 양의 progress와 회차 감상을 사용자·작품·회차 기준으로 중복 제거해 LEGACY 이력을 만든다. Activity만으로 확인되는 회차는 기존 최댓값보다 작거나 같을 때만 이전한다. 회차 감상은 직접 확인된 회차로 이전한다.

각 회차의 가장 이른 남은 생성 시각을 recorded_at으로 보존하되 과거 시청일이 확정됐다는 뜻으로 사용하지 않는다. 현재 progress만 남은 작품은 이 숫자를 과거 모든 회차로 확장하지 않고 기존 작품 진도를 그대로 유지한다. 마이그레이션으로 새로운 피드 활동을 발행하지 않는다.

기존 시청 Activity는 같은 사용자·작품·회차의 이전 이력 ID와 연결한다. 기존 감상으로 대체되어 시청 Activity가 남아 있지 않은 경우에는 과거 스쿼드 공개 범위를 추정해 복구하지 않는다. 기존 화면에서 보이던 감상과 활동을 삭제하거나 새로 공개하지 않는다.

후속 주간·월간 리캡은 episode_watch를 기준으로 해당 기간의 최초 기록 회차 수와 고유 작품 수를 계산할 수 있다. LEGACY는 날짜 정확도가 낮으므로 기간 통계에서 제외한다. 여러 스쿼드 복제본과 감상 수정은 집계하지 않는다. UTC 시각을 저장하고 리캡 기간·표시 시간대는 후속 리캡 설계에서 확정한다.

이번 데이터만으로 `실제 몇 분을 봤는지`, `그 주에 몇 작품을 완주했는지`, `몇 번 재시청했는지`를 계산한다고 약속하지 않는다. 기간별 완주에는 별도의 상태 전이 시각 설계가 필요하다. 이력 삭제는 향후 통계에서도 제외된다.

## 검증 기준

1. 스쿼드가 없어도 회차 이력이 생성되고, 같은 회차 재시도·동시 요청·여러 스쿼드 가입 시 원본은 하나다.
2. 2화→5화는 5화만 새로 기록한다. 현재 진도보다 낮은 미기록 회차도 보존하며 진도는 후퇴하지 않는다.
3. 감상을 추가·수정·삭제해도 시청 이력 수와 최초 시각은 그대로다. 평점만·글만 있는 감상도 유지된다.
4. 시청 이력 삭제, 작품 제거, 계정 삭제가 원본·감상·피드와 일관되고 타인의 기록을 변경할 수 없다.
5. 1→2→3화, 간격 2시간 초과, 다른 사용자, 다른 작품, 빠진 회차, 역순, 감상 추가·삭제를 구분해 표시한다.
6. 다중 스쿼드 복제와 서로 다른 공개 범위, 페이지 경계와 마지막 페이지에서 중복·누락·잘못된 커서가 없다.
7. 홈·내 작품·상세·확장 기본 동작에서 감상 입력 없이 기록할 수 있다. 이미 기록한 회차에 감상을 붙일 때 다음 회차가 선택되지 않는다.
8. 기존 1.0.6 자동 기록 요청과 WatchEntry 응답이 호환된다. 새 확장은 기존 라프텔 실제 재생·SPA 전환·작품 매칭 검증을 통과한다.
9. LEGACY 이전에서 다중 스쿼드를 중복 집계하거나 progress로 빠진 회차를 만들어내지 않으며 새로운 피드를 발행하지 않는다.

## 진행과 남은 결정

구현 순서는 원본 이력·마이그레이션과 호환 API, 피드 표시·묶기, 웹과 확장 입력 흐름, 통합 검증 순서다. 서버를 먼저 배포해 구형 확장과 호환되는 상태를 만든 뒤 웹·확장을 배포할 수 있다. 실제 운영 배포는 구현 검증 후 사용자의 배포 요청 범위에 맞춘다.

2시간 묶기 간격, 탭 이름·URL 추가, 삭제 시 현재 진도 보존 규칙, 과거 데이터를 LEGACY로 구별하는 방식은 작성자의 제안이다. 사용자에게 이미 합의된 사항으로 취급하지 않는다. 이 문서 승인 때 함께 확인한다.

컴포넌트 분리 방식, 정확한 레이아웃·간격, 쿼리 구현·잠금 수단, 테스트 배치는 기존 코드 스타일에 맞춰 구현자가 정한다. 외부 의존성·새로운 연결 권한은 추가하지 않는다.
