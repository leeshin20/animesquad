# AnimeSquad Chrome 확장 프로그램 브랜드 UI 개선 설계

- 작성일: 2026-07-18
- 상태: 사용자 승인 완료
- 범위: Chrome 확장 프로그램 팝업 UI와 확장 프로그램 아이콘

## 1. 목표

Chrome 확장 프로그램의 기존 짙은 남색·분홍색 UI를 AnimeSquad의 리본형 `A` 로고와 초록색 브랜드 시스템에 맞춘다. 기록 기능과 API 흐름은 유지하면서 정보 계층, 입력 가독성, 상호작용 상태와 접근성을 개선한다.

선택한 시각 방향은 `Compact Focus`다. 웹 서비스와 같은 흰색·neutral 기반의 미니멀한 인상을 유지하고, 작은 팝업 안에서 작품 확인과 기록 동작을 빠르게 완료할 수 있도록 단일 화면에 간결하게 배치한다.

## 2. 변경 원칙

- 기존 로그인, 기록 없음, 기록 작성, 완료의 네 화면과 전환 조건을 유지한다.
- `popup.js`의 API 호출, Chrome Storage 처리, 별칭 학습과 자동 종료 흐름은 변경하지 않는다.
- 기존 이벤트 연결에 사용되는 요소 ID를 유지한다.
- 마크업과 CSS는 브랜드 표현, 정보 계층, 접근성에 필요한 범위에서만 수정한다.
- 경고와 오류에는 각각 amber와 red를 유지해 브랜드 초록과 상태 의미가 섞이지 않게 한다.

## 3. 브랜드 적용

팝업 상단에는 리본형 `A` 심볼과 실제 텍스트 `AnimeSquad`를 결합한 로고 락업을 표시한다. 로고 기하는 웹의 `frontend/public/brand/logo-mark.svg`와 동일하게 유지하며 확장 프로그램 내부에서 로컬 SVG 자산으로 참조한다.

| 역할 | 값 | 확장 프로그램 용도 |
|---|---|---|
| Brand Bright | `#22C55E` | 로고 주 면과 비텍스트 장식 |
| Brand Strong | `#15803D` | 기록하기 버튼, 강조 텍스트, 키보드 포커스 |
| Brand Soft | `#DCFCE7` | 감지·선택 상태 배지와 검색 결과 선택 배경 |
| Brand Light | `#4ADE80` | 로고의 제한적인 하이라이트 |

기본 배경은 흰색, 팝업의 본문과 테두리는 neutral 계열을 사용한다. 주요 CTA에만 Brand Strong을 사용하고 보조 버튼은 흰색 배경과 neutral 테두리로 표현한다.

## 4. 레이아웃과 컴포넌트

팝업 너비는 `320px`, 내부 기본 여백은 `18px`로 설정하고 모든 상태 화면에서 같은 로고 락업과 시각 언어를 사용한다.

### 4.1 기록 화면

정보 순서는 다음과 같다.

1. 로고 락업과 `시청 감지됨` 상태 배지
2. 작품명과 `다른 작품 선택` 보조 동작
3. 워치리스트 자동 추가 안내
4. 화수와 평점
5. 한줄평
6. `기록하기` 주요 버튼과 `무시` 보조 버튼
7. 기록 실패 상태 메시지

화수와 평점은 한 행에서 빠르게 확인할 수 있게 구성한다. 팝업 폭이 좁아 내용이 겹치지 않도록 화수 입력 영역에는 고정된 최소 너비를 주고 평점 영역은 남은 공간을 사용한다.

한줄평은 기존 한 줄 `input` 대신 높이 `72px`의 `textarea`로 변경한다. `maxlength="280"` 제한은 유지하고, 세로 크기 조절은 비활성화해 팝업 레이아웃이 임의로 깨지지 않게 한다. 입력 내용은 자동 줄바꿈되어 2~3줄을 한눈에 확인할 수 있어야 한다.

### 4.2 로그인 화면

로고 락업, 짧은 연결 안내와 `animesquad.me에서 로그인` CTA를 표시한다. CTA는 Brand Strong 배경과 흰색 텍스트를 사용하며 기존처럼 웹사이트를 새 탭으로 연다.

### 4.3 기록 없음 화면

로고 락업과 차분한 빈 상태 안내를 표시한다. 지원 서비스와 10분 감지 조건은 기존 문구의 의미를 유지하되 읽기 쉬운 행간과 너비를 사용한다.

### 4.4 완료 화면

리본형 `A` 심볼, 초록 체크와 `기록 완료!` 메시지를 중앙에 표시한다. 기존과 동일하게 `1200ms` 뒤 팝업을 닫는다.

### 4.5 검색 결과

검색 입력과 결과 목록은 neutral 테두리를 사용한다. hover 상태는 연한 neutral, 선택 상태는 Brand Soft 배경과 Brand Strong 텍스트로 구분한다. 결과 목록의 최대 높이와 스크롤 동작은 유지한다.

## 5. 상호작용과 접근성

- 모든 버튼과 입력 요소에 키보드로 식별 가능한 Brand Strong 포커스 링을 제공한다.
- hover, active, disabled 상태가 기본 상태와 시각적으로 구분되어야 한다.
- 화수, 평점, 한줄평에는 연결된 텍스트 레이블 또는 동등한 접근 가능한 이름을 제공한다.
- 평점 영역은 `radiogroup`, 각 별은 `radio` 의미를 갖는 버튼으로 구성한다. 클릭과 방향키로 값을 선택할 수 있고 현재 값은 `aria-checked`로 전달한다.
- 기록 상태 메시지는 기존 `role="status"`를 유지한다.
- 경고 문구는 색상만으로 의미를 전달하지 않고 텍스트 또는 아이콘을 함께 사용한다.
- 본문과 주요 버튼 텍스트는 WCAG AA 수준의 대비를 만족해야 한다.

## 6. 확장 프로그램 아이콘

기존 아이콘을 AnimeSquad 앱 아이콘형 리본 `A`로 교체한다. Chrome UI에서 필요한 `16`, `32`, `48`, `128px` PNG를 동일한 벡터 기하에서 생성한다.

- 배경: Brand Bright `#22C55E`
- 주 심볼: 흰색
- 보조 면: Brand Soft `#DCFCE7`
- 각 크기는 manifest의 `action.default_icon`과 최상위 `icons`에 명시한다.

작은 크기에서도 `A` 실루엣이 뭉치지 않아야 하며, 기존 PWA 앱 아이콘과 동일한 브랜드로 인식되어야 한다.

## 7. 데이터와 오류 흐름

데이터 흐름은 변경하지 않는다.

1. `/api/me` 결과에 따라 로그인 화면 또는 다음 상태를 선택한다.
2. Chrome Storage의 `pending` 유무에 따라 기록 없음 또는 기록 화면을 표시한다.
3. 기존 자동·수동 작품 선택과 워치리스트 확인 로직을 유지한다.
4. 기록 성공 시 pending과 badge를 정리하고 완료 화면을 표시한다.
5. 기록 실패 시 현재 입력을 유지하고 화면 안의 오류 메시지로 재시도를 안내한다.

로딩 중에는 기록 버튼의 비활성화와 `기록 중...` 문구를 유지한다. 오류가 발생해도 팝업의 높이가 크게 튀지 않도록 상태 메시지 공간과 간격을 일관되게 처리한다.

## 8. 테스트와 검증

### 자동 검증

- 팝업 마크업 테스트에서 로고 자산, 네 화면, `textarea`, 280자 제한과 접근성 속성을 확인한다.
- 기존 팝업 동작 테스트를 모두 실행해 로그인, 기록, 재시도, 수동 매칭과 별칭 학습 흐름의 회귀가 없음을 확인한다.
- manifest 테스트에서 `16`, `32`, `48`, `128px` 아이콘 경로를 확인한다.
- 생성된 아이콘 파일의 형식과 실제 픽셀 크기를 확인한다.

### 시각 검증

- 팝업의 로그인, 기록 없음, 자동 매칭, 수동 검색, 오류, 완료 상태를 확인한다.
- 작품명이 길거나 한줄평이 여러 줄인 경우에도 버튼과 입력 영역이 겹치지 않아야 한다.
- 100% 브라우저 배율에서 320px 팝업 안에 가로 스크롤이 없어야 한다.
- 마우스와 키보드 모두에서 hover, focus, active, disabled, selected 상태를 식별할 수 있어야 한다.
- Chrome 툴바에서 16px 아이콘의 `A` 실루엣이 식별되어야 한다.

## 9. 스코프 외

- API, 인증, 저장소와 별칭 학습 로직 변경
- 새로운 화면 상태나 기록 기능 추가
- 팝업 프레임워크 도입 또는 JavaScript 구조 재작성
- 다크 모드
- 사용자가 조절 가능한 textarea 크기
- 지원 스트리밍 서비스 추가
